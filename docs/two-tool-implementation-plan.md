# План перехода к двум инструментам

Дата: 16.10.2026. Денежный ограничитель $30 на 10 000 компаний снят по решению пользователя. Любые будущие пороги устанавливаются только после измеренных тестов; расходы и резервы API продолжают учитываться.

## 1. База до рассылки — быстрый первый проход

- [x] Выделить отдельный запуск без оффера отправителя и без обязательного API-ключа. Старый конвейер сохранить доступным для просмотра прежних результатов.
- [x] Сохранить группировку исходных контактных строк по названию и ИНН, а также привязку к исходным листам и строкам.
- [x] Сформировать широкие аудитории только по явно указанному виду деятельности; неизвестное и неоднозначное — «Общее». Не выдавать вероятную проблему за факт.
- [x] Подготовить единый `mailing.xlsx` с постоянными ID в каждой строке, отдельные файлы аудиторий без служебных колонок, `integration.csv` для сверки и отдельный файл исключений. Исключения не входят в файл для рассылки.
- [x] Вывести отдельную форму и просмотр результатов; расходы показывать без стоп-порога.
- [x] Добавить ручную проверку аудитории/исключения с причиной и журналом: изменение делает предыдущий экспорт недействительным.
- [x] Прогнать без платных запросов на копии 1000 компаний / 1170 строк: импорт 0,68 с, классификация 0,78 с, экспорт 3,69 с; API $0. Сформировано восемь широких аудиторий для 205 компаний, 795 оставлены в «Общем». Это проверка работоспособности и охвата, **не проверка точности**.
- [ ] Разметить выборку назначенных компаний и «Общего» вручную без подсказки текущего решения. Измерить точность и причины пропусков.
- [ ] По ошибкам разметки расширить категории или добавить выборочный одностраничный сбор данных для неопределённых. Модель использовать лишь там, где её прирост качества оправдывает стоимость и время.
- [ ] Повторить пилот на новой разнородной выборке, измерить сквозное время, охват, ошибки, API-расходы и долю ручной проверки. После этого решать о запуске всей базы.

## 2. Заинтересованные лиды — отдельный глубокий процесс

- [ ] Добавить устойчивые сущности для партий лидов, ответов и отчётов; не писать их в `Run/Company.group` первого инструмента. Создать миграцию БД и проверить переход с имеющихся данных.
- [ ] Принимать выгрузку ответов с `source_row_id`, `company_id`, `export_id` из `mailing.xlsx` и самостоятельный список лидов. Потерянные/противоречивые ID направлять на ручное сопоставление. Повторный `reply_id` не дублировать.
- [ ] Дать пользователю подтвердить интерес, отказ, просьбу уточнить или неоднозначный ответ. Глубокое исследование запускать только для подтверждённого интереса или вручную выбранного лида.
- [ ] Исследовать вопрос конкретного лида и сопоставить с реальными услугами отправителя. В отчёте разделить цитату ответа, проверенные факты со ссылками и датами, гипотезы, варианты предложения и открытые вопросы.
- [ ] Проверить импорт, повторные ответы, ручную связку, качество отчётов и расход на лид на 5–10 кейсах. Первый инструмент и его экспорт при этом не пересчитывать.

## Решение по качеству

Текущий быстрый классификатор намеренно консервативен: он не делает вывод о спросе или проблеме компании и не идёт в сеть. На сохранённой базе в «Общем» осталось 79,5%. Поэтому файлы технически готовы, но массовую рассылку по новым аудиториям следует оценивать после выборочной ручной разметки. Ограничитель расходов нельзя подменять сокращением качества: измеряем стоимость и качество каждого следующего обогащения отдельно.
