# Смысловая сегментация по всем профилям

Новый режим `semantic-profiles-v1` включён при создании исследования через интерфейс. Старые запуски сохраняют прежнюю методику до явного повторного прогона.

## Процесс

1. Для каждого профиля выбираются все подтверждённые HIGH-признаки со ссылками на актуальные проверенные доказательства компании/продукта. Менее двух признаков — явная причина недостаточности.
2. Все подходящие профили передаются модели порциями по объёму данных. Пропуска по отсутствию точной пары или заранее заданного правила нет. Профили не урезаются до первых N фактов. Если один профиль или обзор групп превышает безопасный размер, обработка явно останавливается, а не молча теряет данные.
3. Модель получает реальные услуги отправителя и предлагает общие ситуации сотрудничества. В каждой последующей порции видны уже предложенные группы; новые участники могут присоединяться с сохранением общего предложения.
4. Для каждого участника проверяются два различных существующих признака и их evidence_ids. Модель не может назначить компанию из другой порции или использовать выдуманный признак. Для неназначенных сохраняется причина; отсутствующий ответ тоже отмечается явно.
5. Группа из одного участника остаётся только кандидатом и не проходит в итог. Лимита в три сегмента нет.
6. Общие предложения проходят существующую содержательную проверку с цитатами и контрольными неучастниками. Только после этого выполняются классификация и экспорт.

## Проверено локально

171 тест, frontend build. Новые проверки: более трёх групп, рассмотрение всех переданных профилей, отбрасывание выдуманных признаков, объединение участников из разных порций.

На сохранённой базе из 1000 компаний 501 профиль имеет минимум два подходящих признака и может пройти содержательное рассмотрение. Это доступность входных данных, не число будущих назначений. Прежний отбор кандидатов охватывал 113 компаний.

Платный прогон новой схемы пока не выполнялся. Существующие 3 сегмента/25 компаний не изменены.

## Ограничения

Содержательность двух разных признаков и связь с услугой проверяет ревьюер: разные технические имена не гарантируют разных по смыслу фактов. Порядок порций может влиять на предложения; обзор предыдущих групп снижает, но не устраняет этот эффект. Межпорционное объединение требует одинакового предложения, а не только похожего имени. Охват, стоимость и время надо измерить на сохранённых данных перед масштабированием. Повторный обход сайтов для этого не нужен.
