# План исправления сегментации после теста на 100 компаниях

Дата: 12.10.2026. Цель — получить проверяемые общие сегменты для массового письма, сохранив право системы честно воздержаться. Исходное исследование 100 компаний и его отчёт остаются неизменными; повторный сбор сайтов не нужен.

1. **Зафиксировать контроль.** Сохранить агрегаты теста: 51 профиль с признаками, 20 безрезультатных вызовов сегментации, $0.790188 на этом этапе, 383,1 с API и две пары с ≥2 общими конкретными HIGH-признаками, разнесённые по партиям. Тесты должны воспроизводить потерю пар на старом алгоритме.
2. **Глобальный поиск кандидатов.** Вынести подтверждённые конкретные факты из всех профилей в компактный реестр `company → criterion → raw signal/value → evidence`. Найти пересечения до разбиения для модели. Близкие значения могут быть предложениями для проверки, но не становятся подтверждённой эквивалентностью автоматически; связи продукта, покупателя и применения не складываются из разрозненных цитат.
3. **Дешёвый модельный обзор.** Передавать модели компактные группы и общий оффер из документа, а не полные профили по случайным партиям. Ограничить число и размер запросов; при отсутствии кандидатов возвращать объяснимое воздержание. Полные доказательства поднимать адресно на этапе проверки кандидата.
4. **Рецензия и классификация.** Сверять каждое правило с реальной услугой отправителя, исходными `signal.name`, цитатами и URL компаний. Для применимости не приписывать проблему; для гипотезы нужны независимые основания, для события — проверенная дата. Не назначать компанию по одному общему факту каталога. Сохранять трассу включения и отказа.
5. **Исправить изоляцию пилота и измерение.** При создании выборки формировать актуальный `source_filters` вместо текста о 25 компаниях. Добавить агрегированный аудит токенов, модели, расходов и API/gate time без контактов и ключей. Отдельно проверить завышенную оценку допуска токенов (~3,7 раза) ограниченным A/B, не смешивая её с оценкой качества сегментов.
6. **Проверить на сохранённых данных.** Сначала офлайн-тесты и две известные пары; затем один ограниченный повтор только сегментации по замороженным 100 профилям. Сравнить число кандидатов, принятые сегменты, ложные назначения, `UNKNOWN`, вызовы, стоимость и время. Случайные 80 и диагностические 20 оценивать отдельно. Независимая слепая проверка должна пройти прежде чем запускать новую массовую выборку или этап промпта.

Критерий успеха — не заданное число сегментов, а доказанная уместность общего предложения минимум для двух компаний, отсутствие неподтверждённых утверждений, воспроизводимая трасса и меньшая цена за корректное назначение. Ориентир $0.10–0.25 на компактную сегментацию этих сохранённых профилей предварительный и подлежит замеру; целевые $50–100 на 10 000 компаний нельзя обещать по нулевому результату первого теста.

## Выполнено в ограниченном повторе 12.10.2026

Офлайн-поиск на 51 профиле с признаками исключил две ложные точные пары и нашёл один проверяемый канальный кандидат: два производителя с разными товарами и публичным упоминанием дилеров. Семантические лексические подсказки не дают назначения автоматически. Правило хранит для каждой компании исходные `signal.name` и evidence IDs. Два факта могут подтверждаться одним официальным источником при `applicability`; для `hypothesis`/`event` это не считается независимым основанием.

Ограниченный повтор **только сегментации** на сохранённых 100 компаниях сделал 2 вызова модели (обзор и рецензия), занял 48,5 секунды и добавил $0.033828 оценочных расходов приложения; повторного сбора страниц и поисков не было. Модель предложила один общий сегмент `business_development`, рецензия приняла его, классификатор назначил 2 компании по их собственным двум проверенным фактам. Независимая проверка обеих назначенных компаний не нашла ложного включения, но не измеряла полноту всей выборки. Из пользовательских полей сегмента редакционно удалены служебные формулировки о review и кандидатах. Полный расход исходного запуска вместе с повтором — $0.982054 оценочно.

Следующий этап — слепая разметка случайных 80 и диагностических 20, затем проверка более широкого набора типизированных канальных/продуктовых правил на другой выборке. Текущий прототип нашёл только две назначаемые компании; он не доказывает охват или бюджет для 10 000.
