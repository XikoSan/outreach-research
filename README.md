# XTECH Research

Локальное приложение для исследования компаний, сегментации базы и подготовки документов с промптами для внешнего генератора писем. Само приложение письма не отправляет.

## Запуск

Python 3.12+, Node.js 22+ и npm. Из каталога проекта:

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.lock
.venv/bin/pip install --no-deps -e .
npm ci --prefix frontend
npm run build --prefix frontend
cp .env.example .env
./scripts/start.sh
```

Откройте http://127.0.0.1:8000. Если порт занят, остановите старый сервер либо используйте `PORT=8001 ./scripts/start.sh`. Скрипт запускает API и один worker, применяет миграции и останавливает оба процесса по Ctrl+C. После аварийного перезапуска незавершённые задания переходят на паузу.

API-ключ задаётся в разделе «Настройки» для всего рабочего пространства. Он хранится отдельно от базы в `data/credentials/` (каталог 0700, файлы 0600; без шифрования), не попадает в ответы API, снимки и экспорт. Замена применяется со следующего вызова. При обновлении единственный ранее использованный ключ переносится автоматически; если ключи профилей различались, выберите нужный вручную. `OPENAI_API_KEY` из окружения не используется. Проверка ключа обращается к списку моделей, не запускает исследование и не гарантирует доступ ко всем моделям конвейера.

Без ключа доступны импорт, описания предложений, профили и просмотр сохранённых результатов. В исследовательские запросы отправляются описание предложения и публичные материалы компаний; персональные контактные столбцы Excel не отправляются модели.

## Работа

1. Создайте описание «Что предлагаем клиентам»: достаточно короткого текста о деятельности, решаемых задачах и ограничениях. Можно загрузить DOCX, MD или TXT. Приложение сохраняет оригинал и извлекает начальный фрагмент как бесплатный черновик — это не смысловое AI-резюме. Проверьте и отредактируйте его перед использованием. Описание можно переиспользовать; исследование фиксирует его снимок.
2. Создайте исследование: название, XLSX, описание предложения и лимит API. Отправитель на этом этапе не нужен. По умолчанию исследуется вся база; пилот включается явно. Модели выбираются сервером по этапам.
3. Запустите обработку. В разделе отчётов доступны подготовка базы, найденные источники, исследования по направлениям, сводные профили и проверка сегментации. Старые исследования показывают только ранее сохранённые сведения. Пауза действует на ближайшей контрольной точке; текущий запрос может завершиться.
4. Исследование заканчивается сегментами и гипотезами, без автоматического создания промптов. Ознакомьтесь с краткими карточками и подробностями. Рекомендация учитывает подтверждённые признаки и противоречия, но не прогнозирует отклик.
5. Выберите сегмент, компании или отдельные исходные строки контактов. Укажите тип получателя, желаемый следующий шаг и отправителя: сохранённый профиль либо новые данные с возможностью сохранить профиль. Создайте отдельный комплект с собственным лимитом API.
6. Готовый комплект содержит Excel выбранных контактов, документ с промптом и снимок параметров. Контакты, гипотеза и отправитель зафиксированы; для другой версии создаётся новый комплект без повторного исследования. Пауза, продолжение и сверка неопределённых расходов доступны отдельно для комплекта.
7. Общий экспорт исследования содержит Excel по сегментам и статусам. Статусные группы можно подготовить к повторной обработке. Для компании без сайта/официальной соцсети исправьте исходный файл и импортируйте новое исследование.

Профили отправителей можно переименовывать и удалять. Новые поля пустые. Изменения профиля не меняют уже созданные комплекты. API-ключ не связан с профилями.

Исходные строки, дубликаты, порядок колонок и типы ячеек сохраняются. При экспорте проверяются отпечатки строк, количество и отсутствие потерь/повторной выдачи одной исходной строки. Формулы, объединённые ячейки и внешние Excel-ссылки отклоняются явно. Поддерживаются обычные таблицы с заголовками в первой строке.

## Модели и бюджет

Маршрутизация моделей задана на сервере отдельно для поиска, извлечения, сводного профиля, сегментации и промптов. Исходная конфигурация использует Luna для первых трёх этапов и Sol для двух последних. Доступность конкретных ID необходимо проверить в своём API-проекте. Ошибка доступа/отсутствующая модель останавливает запуск.

Перед API-вызовом в БД резервируется консервативная оценка стоимости. Поисковые запросы резервируют особенно большой запас на контекст поиска: маленький бюджет может остановить обработку до его фактического расходования. Расходы интерфейса являются оценкой, окончательный биллинг — в кабинете провайдера. Успешные ответы кэшируются по содержимому запроса. Неопределённый результат сетевого вызова не повторяется автоматически: требуется сверка затрат в кабинете и запись результата во вкладке журнала. Это предотвращает незаметную повторную оплату.

## Хранение и Docker

Локально SQLite и файлы находятся в `data/`; `.env` и `data/` исключены из Git. Для резервного копирования остановите приложение и сохраните весь `data/` вместе с `.env` в защищённом месте.

В Docker используется PostgreSQL и отдельный worker:

```bash
# В .env задайте POSTGRES_PASSWORD (буквы и цифры)
 docker compose up --build
```

Тома `postgres` и `files` постоянные. Не удаляйте их при обновлении. Docker-конфигурация подготовлена, но в текущем окружении не проверялась. Интерфейс рассчитан на одного локального пользователя; аутентификации для публичного размещения пока нет.

## Проверки

```bash
.venv/bin/pytest -q
npm run build --prefix frontend
```

Интеграционные тесты используют настоящие БД и XLSX, подменяя только сеть и модель. Проверяются конвейер, частичный экспорт, продолжение после сбоя, бюджет, кэш ответов, неопределённые вызовы, доказательства, независимость источников, история профилей, перенос и замена глобального ключа, отдельные комплекты, выбор контактов и неизменность снимков, прогресс и фильтры. Платные API-вызовы при разработке не выполнялись. Интерфейс проверяется на отдельной контрольной базе.

Список исследований загружается страницами по 20, компаний и контактов — по 40. На главном экране исследования видны общее число компаний и исходных контактных строк; расходы показаны отдельно. Подробности содержат признаки, цитаты, ссылки, даты, гипотезу, ограничения и противоречия. Миграция 0004 добавляет описания предложений, промежуточные отчёты и независимые комплекты, сохраняя прежние исследования.

## Границы текущей версии

Это работающий первый срез, а не полная реализация всех пунктов [ТЗ](development_spec_source.md). Уже есть постоянное хранение, пять направлений исследования, сопоставление в профиль, сегментация по базе, проверка доказательств, отдельные модели, документы-промпты, экспорт и продолжение обработки.

Остаётся до промышленного использования:

- проверить качество исследований и доступность моделей на реальном API и пользовательской базе;
- добавить браузерный сбор JavaScript-страниц: текущий HTML-сборщик не читает закрытые/динамические соцсети, такие источники отмечаются недоступными;
- реализовать целевое доисследование из резервного бюджета и полные правила ранжирования пересекающихся сегментов (сейчас пересечение выводится в AMBIGUOUS);
- расширить программную проверку актуальности для новостей/вакансий и остальных типов: сейчас жёсткая 30-дневная проверка действует на соцсети/форумы;
- добавить параллельную обработку компаний, расширенные автоматические повторы и оценку качества на размеченной выборке;
- уточнить независимость источников на платформах с несколькими авторами: сейчас используется консервативное сравнение доменов.

Недоступные сведения не превращаются в утверждение об отсутствии проблемы; слабые доказательства не должны назначать сегмент. Инструкции в исследуемых материалах считаются содержимым источника и не управляют конвейером.
