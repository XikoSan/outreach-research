# ReachLab — базы и заинтересованные лиды

Локальное приложение готовит широкие группы компаний для первого письма о сотрудничестве, затем помогает исследовать компании ответивших людей. Оно не отправляет письма.

## Запуск

Требуются Python 3.12+, Node.js 22+ и npm. Из каталога проекта:

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.lock
.venv/bin/pip install --no-deps -e .
npm ci --prefix frontend
npm run build --prefix frontend
cp .env.example .env
./scripts/start.sh
```

Откройте [локальное приложение](http://127.0.0.1:8000/). Скрипт запускает API и один worker; Ctrl+C останавливает оба процесса. Данные хранятся в `data/`, API-ключ — отдельно в `data/credentials/`. Ключ добавляется через кнопку «API».

## Первый инструмент

1. Нажмите «Новая база». Укажите название, фильтры исходной выгрузки и XLSX с контактами. Добавьте текст предложения или загрузите DOCX, MD либо TXT и проверьте извлечённый текст.
2. После запуска модель один раз формирует широкие группы из предложения и видов деятельности, указанных в базе. Скрипт распределяет компании по группам. Он не утверждает, что у компании есть проблема или готовность купить услугу. Неоднозначные компании остаются в «Общем».
3. Для компаний в сформированных группах приложение проверяет вакансии на сайтах, указанных в базе. Ссылка на релевантную вакансию становится дополнительным сигналом для первого письма. Отсутствие подтверждения не меняет группу и не означает отсутствие потребности. Проверка сайтов не делает платных поисковых запросов к модели.
4. Откройте результат, при необходимости измените группу компании с указанием причины, затем создайте ZIP. `mailing.xlsx` сохраняет исходные контактные строки и добавляет постоянные ID, группу и сигнал вакансии. В ZIP также есть отдельные файлы групп, исключений, `integration.csv` и `audiences.json`.

Расходы API показываются без ограничителя. Один или два вызова модели нужны для подготовки групп; стоимость и время на реальной базе пока нужно измерить пилотом. Автоматическая проверка вакансий ограничена официальным сайтом из базы и ссылками с него; она может пропускать вакансии на внешних платформах или страницах без доступных ссылок. Доля пригодных групп также требует ручной оценки на размеченной выборке.

## Второй инструмент

После получения ответа откройте «Добавить лида». Выберите исходную базу и контакт по названию компании или почте, при необходимости уточните имя и должность ответившего. Вставьте его ответ и оффер, выберите глубину исследования: краткое (ответ и сайт), обычное (при необходимости вакансии, соцсети и отзывы) или расширенное (также целевые обсуждения и форумы). Новое исследование использует исходные данные компании и контакта, но не переносит прежнюю сегментацию и гипотезы.

В профиле лида отдельно доступны отчёт с источниками и рекомендации по предложению. Отчёт можно прочитать и скачать в Markdown. Письмо создаётся только по запросу в профиле; пользователь может выбрать рекомендацию и скачать текст письма. Если рекомендации не обоснованы, письмо отвечает на выраженный интерес и задаёт уточняющий вопрос без выдуманных обещаний.

Для извлечения сведений используется GPT-6 Luna, для итогового отчёта и письма — GPT-6.1 Sol. Исходы API-вызовов, расход и резерв сохраняются. Внешние соцсети и форумы используются как актуальные сигналы только при подтверждённой дате публикации за последние 30 дней. Уровни ограничивают ширину поиска; после достаточных сведений дальнейший поиск не выполняется. Качество отчётов на реальных заинтересованных лидах ещё требует пилотной оценки.

Старые исследования и данные сохранены в БД и API. Описание прежнего сценария — в [архивной инструкции](docs/legacy-readme-2026-10-16.md), исходный план — в [плане реализации](docs/two-tool-implementation-plan.md).

## Проверки

```bash
PYTHONPATH=backend:. .venv/bin/pytest -q
npm run build --prefix frontend
```

Сводка на странице «Базы» использует компактный реестр названий, ИНН и сайтов, сохраняемый при группировке каждой базы. Отдельный расчёт убирает повторы между базами; компании с конфликтующими ИНН остаются отдельными. «Сегментов определено» считает сохранённые сегменты за всё время, «Исследовано» — число готовых отчётов по заинтересованным лидам.
